# Единый интерфейс AGP: Angular и контекстная справка

Редакция: 2026-11-17. **TARGET.** Выбор Angular и единого современного лёгкого стиля
задан владельцем. [Интерактивный прототип](../../web/console-prototype/README.md)
показывает поведение на демонстрационных данных; это не реализация управления инфраструктурой.
Бизнес-сценарии определены в [UX](ux.md), права и состояния — в [ТЗ](requirements.md).
Групповая модель WAF Zones принята владельцем 2026-11-17; её спецификация —
[WAF Zones](waf-zones.md). Текущий прототип показывает per-resource WAF, не реализацию зон.

## 1. Frontend и границы реализации

Новый v2 frontend: Angular, TypeScript strict, standalone components, typed Reactive Forms,
Signals для локального состояния, Router для navigation/deep links в промышленной реализации.
Одна библиотека компонентов и design tokens для консоли, пользовательского портала,
входа/MFA, recovery и manual. Разные origins сохраняются; общий стиль не означает общие cookies.
Текущий встроенный HTML/CSS/JS frontend v1 остаётся AS-IS до отдельной миграции.

Демонстрация использует Angular 22.2.6, CLI/build 22.2.7 и Node.js 24.21.0;
точные зависимости зафиксированы lockfile. Production baseline выбирается на начало
реализации по [официальной матрице совместимости](https://angular.dev/reference/versions)
и сроку поддержки, а не по слову latest. Обновления оформляются отдельным изменением.
CDK primitives допустимы при необходимости; визуальный стиль определяется AGP tokens,
а не смесью несогласованных сторонних тем. Не подключать второй frontend framework.
Bootstrap/CSS framework не обязателен; icons/fonts/assets поставляются локально, без CDN.

В прототипе navigation и manual используют локальный hash; источники данных — in-memory
fixtures, внешних API/AD/SMTP запросов нет. В промышленном frontend — generated API client,
серверные permissions, CSRF, ETag/CAS, operation polling и state reconciliation.
UI не подменяет безопасность backend. Нельзя переносить demo service в production adapter.

## 2. Визуальный язык

Светлая инженерная консоль: спокойный нейтральный фон, белые рабочие поверхности,
один синий акцент для основных действий, тонкие разделители, умеренные скругления.
Содержимое важнее декоративных графиков. Иконки одного начертания, технические ID и
версии в моноширинном начертании, числа с tabular figures. Статус всегда подписан текстом.

| Token / правило | Базовое значение |
| --- | --- |
| Фон / рабочая поверхность | Светлый slate / белый, без крупной декоративной заливки |
| Основной текст / вторичный | Тёмный нейтральный / контрастный серый; не прозрачность на весь блок |
| Primary | Спокойный синий; одна основная CTA в рабочем контексте |
| Success / warning / error | Зелёный / янтарный / красный плюс текст и иконка |
| Spacing | Шкала 4/8/12/16/24/32 px; одинаковые формы и панели |
| Typography | Локальный system sans; body 14–16 px; hierarchy через размер и weight |
| Controls | Общая высота в одной форме; icon hit area от 32 px, на touch от 44 px |
| Focus | Явный контрастный outline; не удалять стандартный focus без замены |
| Motion | Короткие переходы; учитывать reduced-motion, без бесконечной анимации |

Точные CSS значения хранятся централизованно в tokens, не копируются между страницами.
Поздняя тёмная тема использует те же семантические tokens и отдельную contrast qualification.
Цель доступности — WCAG 2.2 AA; готовность подтверждается проверками, не выбором Angular.

## 3. Рабочее пространство инженера

Постоянная левая navigation, сверху breadcrumbs и текущая область/площадка. В рабочей
области: заголовок → короткое назначение → основное действие → фильтры → данные.
Desktop sidebar не конкурирует цветом с рабочей поверхностью. Поиск и фильтры не теряют
значений при возврате из detail; область действия видна до выполнения операции.

Показательные экраны прототипа:

- Обзор: состояние площадок и задачи, требующие внимания; явно демонстрационные данные.
- Шлюзы: поиск/фильтры, домены, узлы, доступ/MFA, WAF и отдельно observed/deployment state.
- Карточка/редактор: основные поля, политика доступа, защищённое соединение и проверка изменений.
- WAF и защита: выбранный ресурс, действующее назначение, редакция политики,
  срабатывания и узкие исключения; переход из WAF-статуса ресурса.
- Доступ и AD: provider, TLS/CA, groups, MFA и отдельное назначение email-кодов.
- Изменения: черновики, проверка, согласование, применение; этапы не объединяются.
- События: actor/action/time/outcome; пример события не доказывает живую интеграцию.
- Руководство: поиск тем и точные ссылки на нужные разделы, доступные без внешней сети.

Таблицы используют спокойные строки, понятные названия и короткие статусы. Широкая таблица
прокручивается внутри своего контейнера, не всю страницу. Пустой результат содержит
«Сбросить фильтры». Loading/empty/error/stale/unknown различаются; unknown не окрашивается
как healthy. На мобильном navigation сворачивается, форма становится полноширинной.

## 4. Редактирование и проверка

Кнопки используют конкретные действия: «Создать шлюз», «Сохранить черновик»,
«Проверить», «Посмотреть изменения», «Отправить на согласование».
Сохранение не применяет конфигурацию. Ошибки показываются у поля, фокус переходит
к первой ошибке; введённые значения сохраняются. Изменение protection имеет видимые последствия.

Preview показывает semantic diff, цели и ограничения. Approval/deploy проверяются отдельно;
пользователь не получает впечатления, что простой toggle включил WAF на всех узлах.
Закрытие изменённой формы требует выбора «Продолжить редактирование / Отбросить»
либо сохранения в draft. Доступ к справке и manual не вызывает этот вопрос и не сбрасывает форму.
В прототипе переходы только локальные и помечены как demo; successful demo validation
не означает выполненные Nginx/AD/WAF проверки.

### WAF Zones: целевой основной экран

При 1000+ сервисов раздел «WAF и защита» сначала показывает **зоны**. Верхние вкладки:
«Зоны / Политики / Срабатывания / Исключения». Список зон: Site, имя, владелец,
число Gateway/Routes/узлов отдельными колонками, целевая policy revision/режим,
наблюдаемое применение и проблемы. Поиск/фильтры/pagination серверные; sidebar и
простые строки сохраняют единый лёгкий стиль. Иллюстративный счётчик не доказывает fleet capacity.

В карточке зоны: «Состав», «Защита», «Отклонения», «Срабатывания», «История и применение».
Основная CTA зависит от состояния: «Изменить политику зоны» → «Проверить влияние» →
«Подготовить обновление». AND-селектор меток имеет читаемое объяснение и preview
совпадений; ID-список и явный Site default — отдельные варианты. Ambiguous/unassigned
отображаются адресно; нет действия, молча выключающего защиту.

Перед approval панель охвата показывает вошедшие/вышедшие Gateway, replacement
assignments, локальные изменения/rebase, Routes и уникальные узлы. Выбор всех результатов
фиксируется сервером, а новые совпадения показываются отдельно для следующего change.
Полный node diff раскрывает соседние приложения/зоны; canary подписан как выбор узлов,
не процент запросов одного приложения. Несколько Site — отдельные планы/статусы под
одной UI-командой. Partial/offline/unknown не сворачиваются в общий зелёный статус.

На карточке Gateway: «Наследуется из зоны … / база … / локальных исключений …» и
ссылка на effective protection. «Изменить только этот сервис» явно создаёт производную
политику; источники base/local/profile locks/minimum видны рядом с итоговыми значениями.
«?» обязателен для membership, Site default, base/local, rebase, frozen selection,
scope, canary и partial state; manual объясняет последствия без потери dirty draft.

Этот экран — TARGET следующего этапа frontend. Текущий per-resource demo остаётся
полезным примером индивидуального редактора; его фиктивные local checks не закрывают
серверные membership/RBAC/CAS, native WAF или load qualification.

### Индивидуальная настройка WAF

Один вход для изменения WAF — раздел «WAF и защита». В карточке шлюза остаются
действующий режим и переход к настройкам выбранного ресурса. Над вкладками видны
домен, exact target nodes, наблюдаемая ревизия и действующая политика. Рядом явно
выделена редактируемая редакция: переключение её режима не меняет действующую защиту.

- **Политика:** режим «Наблюдение / Блокировка», engine и pinned CRS reference,
  уровень paranoia 1–4 и расширенные входящий/исходящий anomaly thresholds.
  Более высокий paranoia включает дополнительные правила и увеличивает вероятность
  ложных срабатываний; повышение порога, напротив, уменьшает число блокировок.
  Порог — накопленный score, а не число атак и не вероятность атаки.
- **Срабатывания:** время и ревизия/режим в момент события, route, правило, категория,
  безопасное имя поля, score и отдельный WAF outcome. «Не заблокировано WAF» не
  доказывает успешный ответ приложения. Значения query/header/cookie/body не выводятся.
- **Исключения:** только выбранный route, конкретные rule IDs и literal field name;
  обязательны owner, причина, reviewAt и expiresAt с явной временной зоной.
  Событие может предварительно заполнить эти безопасные metadata, но не применить
  исключение. Истечение исключения отражается по контракту [UX §12](ux.md#12-waf-сертификаты-секреты-и-дистрибутивы).

Режим хранится в `Gateway.spec.waf`, параметры/исключения — в `WafPolicy.spec`.
Редактор для одного ресурса создаёт новую копию политики и точное назначение;
не изменяет общую политику других потребителей. В целевом групповом сценарии это
производная policy от exact базы зоны с provenance/rebase. Preview показывает semantic diff,
base revision, новый policy reference и узлы. В prototype локальная проверка формата
отделена от серверной qualification CRS/компиляции/probes. Запрос согласования фиксирует
неизменяемую редакцию, дальнейшее редактирование создаёт новый draft. Применение
и независимое подтверждение rollout остаются следующими этапами промышленной системы.
AD, MFA и Central Auth действуют независимо от выбранного режима WAF.

## 5. Знак «?» и краткая справка

Рядом с ключевым параметром стоит единый `HelpTip`: вопросительный знак в кружке,
визуально вторичный, с самостоятельной областью нажатия. Справка содержит 1–3 коротких
предложения: что означает параметр, на что влияет, какое ограничение важно знать.
Внизу всегда ссылка **«Открыть в руководстве →»** на точную тему внутреннего manual.
Одна только native `title` не считается выполнением требования.

Контракт компонента:

```text
HelpTip(topicId)
topicId -> локальный типизированный реестр справки
краткое объяснение -> popover
подробная тема -> /manual/{topicId}, без внешнего сайта
```

Клик/Enter/Space открывает справку; Esc и нажатие снаружи закрывают. На touch работает tap.
Trigger имеет `type=button`, accessible name «Справка: …», `aria-expanded` и `aria-controls`.
Если popover содержит ссылку, он не объявляется plain tooltip: интерактивное содержимое
получает корректную семантику region/dialog. Фокус может перейти в ссылку и вернуться
к инициатору. Popover не обрезается scroll-контейнером, не выходит за viewport и не
блокирует ввод. Важное ограничение остаётся рядом с полем, даже если справка не открыта.

| Тема | Что кратко объясняет | Исходная спецификация |
| --- | --- | --- |
| `central_auth` | Где проверяется доступ и почему отказ Auth закрывает запрос | [Архитектура](architecture.md) |
| `ad_tls` | DC, защищённый LDAP, проверка CA/имени и отсутствие downgrade | [Identity](identity.md) |
| `ad_groups` | Stable group mapping, nested/primary groups и отдельные management roles | [Identity](identity.md) |
| `mfa` | Обязательность второго фактора, TOTP/IdP и момент выдачи session | [Identity](identity.md) |
| `email_codes` | Назначение, expiry/resend и почему письмо не снимает обязательную MFA | [Identity](identity.md) |
| `waf_mode` | Detection фиксирует события, blocking отклоняет запросы после tuning | [ТЗ](requirements.md) |
| `waf_policy` | Назначение ресурсу, копия общей политики и immutable revision | [UX](ux.md) |
| `waf_paranoia` | Чувствительность правил и вероятность ложных срабатываний | [ТЗ](requirements.md) |
| `waf_thresholds` | Отдельные score thresholds для запроса и ответа | [ТЗ](requirements.md) |
| `waf_exceptions` | Route/rules/field, owner/reason/review/expiry и безопасное удаление | [UX](ux.md) |
| `waf_events` | Контекст события и различие WAF outcome / ответа приложения | [Безопасность](security.md) |
| `upstream` | Куда пойдёт запрос, как проверяется URL/TLS и что не является публичным доменом | [Протоколы](protocols.md) |
| `revision_apply` | Различие draft/validate/approval/deploy и необходимость diff | [UX](ux.md) |
| `drain` | Что происходит с уже открытыми соединениями при изменении/отзыве | [Протоколы](protocols.md) |
| `unknown` | Отсутствие подтверждения, observed time и reconciliation вместо blind retry | [Эксплуатация](operations.md) |

В полном продукте этим же компонентом покрываются scope, inheritance/locks, upstream TLS,
secret reference, deadlines, node ownership, enrollment, revision/CAS, rollout/canary,
RBAC/approvals, token expiry, retention и restore. Изменение значения не вызывается кликом «?».

## 6. Внутренний manual

Для каждой темы: понятный заголовок, краткое объяснение, поведение/ограничения,
пошаговая инструкция, связанные темы, версия документации. Справка и manual используют
один topic ID и согласованный текст. Registry входит в frontend build и работает в
NoInternet profile; markdown/HTML из произвольного внешнего URL не исполняется.
Production renderer использует доверенный sanitized content, без произвольного script/iframe.

В прототипе deep links имеют вид `#/manual/ad_tls`, разделы — `#/gateways`, `#/identity`
и т. п. В промышленном Angular Router — эквивалентные внутренние routes с guard/scopes.
Manual drawer открывается поверх текущей формы, сохраняя FormGroup, ошибки, dirty state,
scroll и контекст. «Назад к настройке» закрывает manual и возвращает фокус на инициатор.
Browser Back/Forward должен оставаться предсказуемым; переход по чужой теме не теряет draft.
Если тема отсутствует/версия устарела, показать безопасное объяснение и поиск manual,
а не пустой экран. Скрытые по scope объекты/секреты в справке не раскрываются.

## 7. Разделение production компонентов

```text
shell/              navigation, breadcrumbs, scope, responsive workspace
ui/                 buttons, fields, badges, tables, dialogs, empty/error states
help/               HelpTip, HelpDrawer, topic registry, internal manual routes
features/gateways/  typed editor, list/detail, semantic preview
features/waf/       resource binding, policy versions, events, typed exceptions
features/identity/  AD/OIDC, MFA, invites/recovery, contacts
features/changes/   revisions, approvals, rollouts и reconciliation
data-access/        generated DTO/client, ETag/CSRF, authoritative operation state
demo/               fixtures/adapters только для prototype/development
```

Разделение — целевая декомпозиция, не обязательная структура малого прототипа.
Демо хранит fixtures отдельно от real adapters. Доступы, drafts и open manual не хранят
credentials в URL/localStorage. Save/CAS errors и session expiry не теряют несекретный draft;
password/TOTP/email-code fields никогда не входят в автосохранение.

## 8. Проверки примера и приёмка продукта

Для примера: production Angular build со strict templates; браузерные search/filter,
create/edit validation, draft/preview, HelpTip → manual → возврат без потери формы;
Esc/focus return и ширины desktop/mobile. Ошибки JS и asset failures учитываются отдельно.
Реальные выполненные проверки фиксируются в README прототипа.

До production дополнительно: автоматическая accessibility проверка плюс ручной screen reader,
keyboard-only, contrast/zoom/reflow, CAS conflict, stale/unknown/timeouts, permission revoke,
session expiry, origin/cookie isolation, localization и совместимость поддерживаемых browsers.
Сборка прототипа не подтверждает прохождение этого production набора.
